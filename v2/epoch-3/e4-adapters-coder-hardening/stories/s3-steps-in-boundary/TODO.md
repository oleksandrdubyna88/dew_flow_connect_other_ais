## Pass 2 of the security verify (2026-11-26, `RESULTS_e4_s3_security_verify.md` at 68164c23): what was done, and the INTERIM decision for the owner

**Interim, owner decides — "frozen build definitions".** The coordinator consulted two models (consask 97493a75); both chose option A; it is the interim decision until the owner decides. It is not in SPEC.md (counted as a possible plan change for the owner).

- **What it is.** Before any restore, and after the worktree has been proven equal to the commit, a coder job's checks compare the WHOLE tree of the head with the base (`git diff-tree -r -z --no-renames --raw`, main repository, hardened reads: paths, modes, ids). The checks are refused (`toolchain_refused`, stop `toolchain-refused`, no step run) with a fixed sentence and two counts when the head added, deleted, modified or mode-changed any path whose file name (without case, at any depth) is on the list in `shared/toolchains.json` (`frozen`), or any symlink or submodule anywhere. It covers detected AND stated (toolchain-file) commands. The list is data: .NET project, props, targets, solution and runner-configuration files, `global.json`, `nuget.config`, lock files, `.config/dotnet-tools.json`; node `package.json` (the whole file), lock files, workspace and runner configuration, `tsconfig*.json`, babel, jest, vitest, mocha, prettier; `.coai/toolchain.yaml`, `.gitmodules`, `.gitattributes`. A scan test holds the code to it (`AFrozenDefinitionsTests`).
- **What it BLOCKS (by design).** A coder cannot add a package or a test project, or change any build file. Such a head is refused, and the person can take it in by hand (the sentence says so). It also blocks fixing a build file when the red test is a build file's fault.
- **Residual, an owner question too.** A script or helper file that a frozen definition invokes (for example `scripts/test.sh` under `scripts.test`) is not frozen, and an existing test of the base can be edited by the head (a test that is changed to pass is not a definition change). The name-level compare of t5 stays as a second layer.
- **Restore on the host network (M9, item 12)** is covered for the head's changes by the gate (a project, a lock file, a `nuget.config`, an `.npmrc` cannot change). Not covered: what the BASE's own files do on the host network, and a repository whose base is already hostile. The options (a) proxy with an allow-list, (b) restore from a cache coai fills stay the owner's.

## Pass 3 of the security verify (2026-11-26, at 9cbd5e57): M15 and M16, still INTERIM, owner decides

**M15 — the gate is now an ALLOW LIST** (the third list of names that leaked: `.user`, `launchSettings.json`, `.projitems`, `.editorconfig`, `vite.config.ts`… each read by a tool by itself). A head may add, modify or delete only a file whose last extension (without case) is in `shared/toolchains.json` `frozen.allowedSourceExtensions` (`.cs .fs .vb .razor .cshtml .ts .tsx .mts .cts .js .jsx .mjs .cjs .css .scss .html .md .txt .snap`) AND whose base name does not match `frozen.configNamePattern` (a regular expression, without case: dot files, `config`, `rc`, `setup`, `global`, `jest`, `vite`, `webpack`, `eslint`… names). Anything else is refused: every other extension, every dot file, every config-shaped name, any symlink or submodule; a rename is a delete and an add. **The three name lists were kept** (as a second layer and as documentation of what the allow list stands for), not dropped. The dotnet MTP test argv carries `--no-launch-profile` (defence in depth; not added to the VSTest argv, whose `dotnet test` has no such option). Tests: the 22 exploit cases plus 21 M15 cases (`AHeadsChangesAreReportedTests`, red on 9cbd5e57), the allow list in `AFrozenDefinitionsTests` (a plain `src/Foo.cs` change and an added `tests/FooTests.cs` pass).

**What a coder can now change: only source files of those extensions.** The residual is unchanged: the head can still edit or delete the base's tests and helper scripts that are source files (`*.js`, `*.ts`, `*.cs`, a test file, a script in `.js`); a script or helper that is not a source file (`test.sh`) cannot be changed, a frozen definition may still invoke it. The envelope now says how many test files the head touched (S21, `headTestFiles`: modified, added, deleted; by file name and folder).

**M16 — the job's folders.** Every check step runs with a home, `/tmp` and `/var/tmp` that are emptied before and after the step (`BoundaryFolders.EmptyForStep`), so nothing a step writes (an MSBuild `ImportAfter` target, an `.npmrc`, a temp file) is seen by the next step or the next round. `nuget-packages`, `npm-cache` and `dotnet-home` are bound writable only in a RESTORE step (`CheckBoundary.RunAsync(..., restore: true)`) and read-only in every other step; the unit record's properties say which. With M15, a restore runs the base's definitions only, so what it writes to the caches comes from the base. Tests with real units: `M16_*`. Not done: the package folders are not emptied at the start of a round (a restore on the next round starts from what the base's restore left; it would cost a re-download per round) — an owner question.

**Shoulds of pass 3.** S21 fixed (above). S22: the `.git`-below-root half is fixed (after the clean, `HasANestedGit` walks the tree; test `S22_*`); the never-checked-out submodule folder is open. S23 (steps share the worktree: run restore and compile first and compare `status --ignored` between two test steps) open. S24 fixed: the refused paths are written, spelled, to `checks/round-<n>/refused-paths.txt` in the job's folder (at most 200), not into the sentence. S25 (clean filters of the operator's git configuration), S26 (trailing dot or space; names with case) open; S13, S16, S18, S20 open from before.

## OWNER DECISION 2026-11-26 — replaces the interim gate: the head's definitions run, and what it changed is REPORTED

The owner: "Let's widen it so the coder is comfortable. Let it restore packages from the internet itself; no proxy or address lists" and, on tests and helper scripts, "if the work needs it, let it do it — allow everything." It **replaces** the interim gate "frozen build definitions" of passes 2 and 3 (the allow list, the old name list, the check-definition compare as a refusal, the lost-step refusal, the `nuget.config`/`.npmrc` rule). The sections above that describe a refusal are history. SPEC §A3, §A4 and the D12/D13 rows were edited to match (**a plan change**, "owner decision 2026-11-26").

- **No refusal for anything the head changes.** The head's own toolchain file and manifests are resolved and run: a package or a test project the coder adds is restored from the internet (host network), built and tested. Only what cannot be run is refused (an unparsable file, a stack with no adapter, a node project with no lock file, an MTP project without the runner setting).
- **Reported** in the envelope (`definitionsChanged`, `definitionSummary`, `toolchain.{changedDefinitionFiles, changedLinksOrSubmodules, lostSteps, changedDefinitions, changedTestCommands}`, `headTestFiles`) and in the job record `checks/round-<n>/changed-definitions.txt`. The lists in `shared/toolchains.json` are the classifier.
- **The accepted risk:** a green check means the head's own definitions passed; the base's tests may have been changed by the coder, and the envelope says when. A helper script or a test the head rewrites to pass is not stopped: it is reported only as a changed file (a source file is not even called a definition); the code gate reads the diff.
- **Kept (cost the coder nothing):** M6 (clean tree, no nested `.git`), M16 (fresh home and temp per step; caches writable in restore only), the hardened git reads, no head value in a sentence, M13 (every detected unit runs), S17 (an unstoppable check unit ends the job).
- **Accepted checkpoint findings, kept:** 1 docs, 2 the `AffectedProjects` split, 3 a workspace member's test and typecheck script planned as its own step (`npm test --workspace=./<member>`; measured: it runs the member's script and returns its exit code), 5 a conditional test marker is a marker, 6 no placeholder echo. **Dropped:** 4 (freezing helper scripts) and 7 (the narrower config-name pattern).
- **Known difference (checkpoint finding 0, rejected by the coordinator):** the PROJECT.md rule "MTP executable, never `dotnet test`" is for agents running this repository on the host. The product's generic detection uses `dotnet test --project <unit> --no-build -c Debug --no-launch-profile` for an MTP unit, measured in the unit; a repository overrides it with `test` in `.coai/toolchain.yaml`.
- **Tests turned from "refused" into "reported and run":** `AHeadsChangesAreReportedTests` (each measured exploit is a case of what the report shows), `AChangedCheckDefinitionIsReportedTests` (D12/D13 and the items of the s2 verify list), `AToolchainIsResolvedTests`, `ADetectedChecksOfACoderJobTests` (D3, D14), `ACoderChecksTests.D3`, `ACoderEnvelopeNamesItsToolchainTests.D1`, the golden answers (the heads that refused now resolve and print their lost and changed lines).
