# s8 todo — what a coder could not meet as written (2026-11-26)

## t1 (cross-vendor failover): how the dod was read, and what is not met

- **Facts table.** `shared/coder-boundary-releases.json` holds verdict `ship` for codex and agy and NO measured release for either, so in the product both count as refused (`CoderVendorRow.Ships` needs a release). A real codex or agy coder cannot start; nothing here starts one. The proof uses an injected table and two TEST vendors that stand in for them (FakeCli answers as the CLI). The real vendor types come with s5 and s6.
- **d1/d2 read as written, with one narrowing.** "Each of the four combinations" is run for ship/refuse; the table's own state (verdict ship, no release) is run as three more rows, because that is what the product holds today. "A model the caller named on a refused vendor is refused before any folder" needed a way to inject the table into `start_role`; `RoleJobService.CoderSet` and an optional argument of `RoleRouting.Plan` were added for it (the product passes its own set, nothing changes there).
- **d3, "the unit of each vendor holds only the sign-in copy or the variable name of that vendor" — a production change, the safer reading.** Before this task every unit got the host's sign-in file, which is claude's: a seam vendor that reuses claude's property list would have bound the person's claude sign-in into a codex or agy unit. `CoderBoundary` now treats every launch of a vendor other than claude as keyless (no claude sign-in bound, the claude key pool hidden, and the preflight rows `sign-in-not-in-unit` and `keys-folder-hidden` ask from inside). The real codex and agy types will bring their own sign-in; they can no longer inherit claude's by accident.
- **d3, "the sign-in copy of the vendor that was left is deleted before the unit of the next vendor starts" — met for the DELETION, not for the MAKING.** The copy is s7 t6 (not built): nothing in the product makes a copy yet. `CoderSignInCopy` / `CoderOsLayer.LeaveVendor` / `RoleFailover.VendorLeft` delete a file at the place the vendor's seam names (`Home(job).SignInFile`) when its recipe is `CopyForJob`, and a copy that cannot be deleted ends the job `coder-boundary` before the next vendor starts. The tests plant the copy from inside the test vendor's unit (FakeCli `homeFiles`). When t6 makes the copy, it must make it at that same path and must make it again before every launch of its vendor (a route that returns to a vendor finds it deleted).
- **Not covered, needs a measured release or a real CLI:** the real argv, the real home layout, the real sign-in file shape, and "a spent quota" as codex or agy report it (the test uses claude's recorded 429 envelope under a codex-named vendor). All of it belongs to s5 t6 / s6 t7 and the paid proofs t3 and t4.
- **FakeCli** gained one model-map field, `readFiles` (absolute paths the fake tries to read at the start of its launch, answered in `sidecars/<pid>.reads`), so a test can say what a unit shows from inside.
- **A defect the test found, fixed here: a claude unit with the person's sign-in left an empty file in the job's home, and the unit of the NEXT vendor was refused for it.** systemd makes the target of a file bind on the host (`<job>/coder/home/.claude/.credentials.json`, 0 bytes) and leaves it when the unit ends; the preflight row `sign-in-not-in-unit` (`-e`) of any later keyless launch of the job then said "bad", so a failover from claude to another vendor would have ended `coder-boundary` on the person's sign-in path. `LeaveVendor` now deletes that empty place (only an empty regular file, never a link) when the job leaves claude.
